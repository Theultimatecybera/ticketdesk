1. Project overview
Build TicketDesk API: a Spring Boot REST backend with MySQL, full CRUD, validation, error handling and JUnit tests, in 7–10 days. It reuses the domain of your HelpDesk Pro project (tickets, users, comments), so you already understand the problem and can focus on learning Java and Spring.
Why this project fits a Java intern resume
• It covers what Java intern interviews ask: OOP, layered architecture, JPA/Hibernate, REST, exceptions, collections and unit testing.
• It sits next to HelpDesk Pro, so you can explain what you rebuilt in Java and why.
• It is small enough to finish and explain line by line. A finished small project beats an unfinished large one.

Package structure (layered architecture)
com.ritik.ticketdesk
├── controller      // HTTP layer: TicketController, CommentController
├── service         // business logic: TicketService, CommentService
├── repository      // DB access: TicketRepository, UserRepository ...
├── entity          // JPA classes: User, Ticket, Comment, enums
├── dto             // request/response objects
├── exception       // custom exceptions + GlobalExceptionHandler
└── TicketDeskApplication.java
The request flow is: Controller → Service → Repository → MySQL. The controller never talks to the repository directly, and entities are never returned to the client; DTOs are. Be ready to explain this in an interview.
3. Database design
Three tables with two one-to-many relationships: one user creates many tickets, and one ticket has many comments. Hibernate creates the tables from your entities (ddl-auto=update), but write the schema yourself once so you understand it.
CREATE TABLE users (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(150) NOT NULL UNIQUE,
  role VARCHAR(20) NOT NULL,            -- USER or ADMIN
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE tickets (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  description TEXT,
  status VARCHAR(20) NOT NULL,          -- OPEN, IN_PROGRESS, RESOLVED, CLOSED
  priority VARCHAR(20) NOT NULL,        -- LOW, MEDIUM, HIGH
  created_by BIGINT NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (created_by) REFERENCES users(id)
);

CREATE TABLE comments (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  ticket_id BIGINT NOT NULL,
  author_id BIGINT NOT NULL,
  message TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (ticket_id) REFERENCES tickets(id) ON DELETE CASCADE,
  FOREIGN KEY (author_id) REFERENCES users(id)
);

CREATE INDEX idx_tickets_status ON tickets(status);
Design points to be able to explain
• status and priority are Java enums stored as strings (@Enumerated(EnumType.STRING)), not numbers.
• The index on status speeds up filtering tickets by status.
• Use @ManyToOne(fetch = FetchType.LAZY) for relations and know why (it avoids loading data you do not need).

Rules to implement
• title is required, 5 to 200 characters. priority must be LOW, MEDIUM or HIGH. Missing or bad input returns 400 with a field-wise message.
• Unknown ticket or user returns 404.
• A status cannot move backwards or skip a step (for example OPEN → CLOSED returns 400). This is real business logic that interviewers like to ask about.
• Duplicate email on user creation returns 409.

public class Ticket {

    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 200)

    @Column(columnDefinition = "TEXT")
    private String description;

    @Enumerated(EnumType.STRING)

    @Enumerated(EnumType.STRING)

    @ManyToOne(fetch = FetchType.LAZY)

    // constructors, getters, setters

Enum with transition rule: entity/TicketStatus.java
public enum TicketStatus {
    OPEN, IN_PROGRESS, RESOLVED, CLOSED;

    public boolean canMoveTo(TicketStatus next) {
        return next.ordinal() == this.ordinal() + 1;
    }
}

Service: service/TicketService.java
@Service
public class TicketService {
    private final TicketRepository ticketRepository;
    private final UserRepository userRepository;

    public TicketService(TicketRepository ticketRepository, UserRepository userRepository) {
        this.ticketRepository = ticketRepository;
        this.userRepository = userRepository;
    }

    public TicketResponse create(TicketRequest req) {
        User user = userRepository.findById(req.createdBy())
            .orElseThrow(() -> new ResourceNotFoundException("User not found with id " + req.createdBy()));
        Ticket ticket = new Ticket();
        ticket.setTitle(req.title());
        ticket.setDescription(req.description());
        ticket.setPriority(req.priority());
        ticket.setCreatedBy(user);
        return TicketResponse.from(ticketRepository.save(ticket));
    }

    public TicketResponse updateStatus(Long id, TicketStatus next) {
        Ticket ticket = ticketRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException("Ticket not found with id " + id));
        if (!ticket.getStatus().canMoveTo(next)) {
            throw new InvalidStatusTransitionException(ticket.getStatus() + " -> " + next);
        }
        ticket.setStatus(next);
        return TicketResponse.from(ticketRepository.save(ticket));
    }
}
Controller: controller/TicketController.java
@RestController
@RequestMapping("/api/tickets")
public class TicketController {
    private final TicketService ticketService;

    public TicketController(TicketService ticketService) {
        this.ticketService = ticketService;
    }

    @PostMapping
    public ResponseEntity<TicketResponse> create(@Valid @RequestBody TicketRequest req) {
        return ResponseEntity.status(HttpStatus.CREATED).body(ticketService.create(req));
    }

    @PatchMapping("/{id}/status")
    public TicketResponse updateStatus(@PathVariable Long id, @RequestParam TicketStatus status) {
        return ticketService.updateStatus(id, status);
    }
}
Global exception handler: exception/GlobalExceptionHandler.java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ApiError> notFound(ResourceNotFoundException ex, HttpServletRequest req) {
        return build(HttpStatus.NOT_FOUND, ex.getMessage(), req);
    }

    @ExceptionHandler(InvalidStatusTransitionException.class)
    public ResponseEntity<ApiError> badTransition(InvalidStatusTransitionException ex, HttpServletRequest req) {
        return build(HttpStatus.BAD_REQUEST, "Invalid status change: " + ex.getMessage(), req);
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiError> validation(MethodArgumentNotValidException ex, HttpServletRequest req) {
        String msg = ex.getBindingResult().getFieldErrors().stream()
            .map(e -> e.getField() + ": " + e.getDefaultMessage())
            .collect(Collectors.joining("; "));
        return build(HttpStatus.BAD_REQUEST, msg, req);
    }

    private ResponseEntity<ApiError> build(HttpStatus status, String msg, HttpServletRequest req) {
        return ResponseEntity.status(status)
            .body(new ApiError(LocalDateTime.now(), status.value(), status.getReasonPhrase(), msg, req.getRequestURI()));
    }
}
Create ResourceNotFoundException, InvalidStatusTransitionException (both extend RuntimeException) and the ApiError record yourself. Constructor injection (not @Autowired on fields) is the better practice and a common interview question.

Service test example: TicketServiceTest
@ExtendWith(MockitoExtension.class)
class TicketServiceTest {

    @Mock TicketRepository ticketRepository;
    @Mock UserRepository userRepository;
    @InjectMocks TicketService ticketService;

    @Test
    void create_throwsWhenUserNotFound() {
        when(userRepository.findById(99L)).thenReturn(Optional.empty());
        TicketRequest req = new TicketRequest("Login broken", "desc", Priority.HIGH, 99L);

        assertThrows(ResourceNotFoundException.class, () -> ticketService.create(req));
        verify(ticketRepository, never()).save(any());
    }

    @Test
    void updateStatus_rejectsSkippingAStep() {
        Ticket t = new Ticket();            // status defaults to OPEN
        when(ticketRepository.findById(1L)).thenReturn(Optional.of(t));

        assertThrows(InvalidStatusTransitionException.class,
            () -> ticketService.updateStatus(1L, TicketStatus.CLOSED));
    }
}

Cases that must be covered
• Create ticket: success, user not found, blank title, invalid priority.
• Status: each valid step passes; skipping a step or going backwards fails.
• Get/delete: existing id works; unknown id returns 404.
• Filtering by status and pagination return the expected page.
• Duplicate email returns 409.
Run everything with mvn test. Put the passing result (a screenshot or a short line) in the README. Check coverage in IntelliJ (Run with Coverage) and aim for about 70% on the service layer; only quote the number you actually measure.
